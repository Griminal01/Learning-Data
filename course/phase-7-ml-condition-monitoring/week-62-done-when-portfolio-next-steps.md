## Session 1 (1.5 h): The non-specialist test

### Prepare a 3-minute explanation (no jargon)

Use this structure, with **your** numbers:

1. **What it does:** *"Each sensor learns what normal looks like for its own bearing. If several readings in a row look very different from normal (6× the usual spread), it raises an alert."*
2. **Why trust it:** *"We tested it on 60 bearings that ran to failure. It warned about every one, on average about 2 months before failure, and never less than about 3 weeks."*
3. **How many false alarms:** *"In testing, none: not on the 4 healthy fans, and not too early on any of the 60. In real life expect some, especially after maintenance or when the fan runs at a different speed, so we'll review every alert for the first 6 months and tune it."*
4. **What to do with an alert:** *"Check it on the next shift with a handheld meter, then plan the bearing change in the next scheduled stop. You usually have weeks, not hours."*
5. **What it won't do:** *"It won't tell you the exact failure date, and it can't see faults on machines without a sensor."*

### Do it

Explain it to someone non-technical: a family member or a friend. Then ask them to explain it back to you. If their version covers points 2, 3 and 4, **you've passed Phase 7**. 🎉 And the whole course.

## Weekend (2 h): What's next

### Use it at work (with permission)

1. Show your manager the Weibull study (06) and the dashboard (03). Ask: *"Could I try this on our real data?"*
2. Agree the **data rules** first: what you can export, where it can live, and who can see it. Never take work data home without written approval.
3. Start with the **lowest-risk, highest-visibility** item: usually the dashboard, or the automated report, on data the team already sees.

### Where the industrial tools fit

| Tool | Why | When |
|---|---|---|
| **Power Automate / Power Apps** | paper-to-mobile forms, approvals, alerts | as soon as you have a work account (Week 23 designs) |
| **Historians** (FactoryTalk Historian, AVEVA PI) | where real process data lives, so learn to query and export it | ask the controls team for read access |
| **OPC UA / MQTT** | how shop-floor data reaches IT systems (IIoT) | next learning project; try a free MQTT broker and pycomm3 at home |
| **Minitab** | common SPC tool in manufacturing | only if your site uses it; Python covers the same |
| **Tableau** | where your Redzone production data lives (Phase 4) | keep it fresh: rebuild one Redzone view a month on Tableau Public |

### Credentials

| Credential | Value |
|---|---|
| **PL-300** (Power BI Data Analyst) | the most recognised data cert in UK manufacturing. Book it if you haven't. |
| **CMRP** (SMRP) | a reliability credential that pairs with this course and your HNC/HND path |
| Kaggle / Coursera certificates | light proof of Python and ML basics |

Ask whether the training budget will fund PL-300 or CMRP, since both map directly onto the PM pillar.

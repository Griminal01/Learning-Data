# Building your portfolio

Each phase ends with a build. Together they make **one connected portfolio**, the evidence that you can do the work, which is worth more than any certificate.

Keep it in your **own public GitHub repo** (e.g. `maintenance-analytics-portfolio`), separate from this course repo. Use only the synthetic data from this course, or public data sets. **Never** put employer data, names or system screenshots in it.

## The seven projects

| Folder | Phase | Project | Skills | Payoff at work |
|---|---|---|---|---|
| `01-pm-compliance-workbook/` | 1 | PM compliance workbook | Excel, Power Query, Power Pivot | replaces manual weekly tallies |
| `02-mini-cmms-sql/` | 2 | Mini CMMS database | SQL, data modelling | understanding of any CMMS's data model |
| `03-lined-dashboard/` | 3 | Line D maintenance dashboard | Power BI, DAX | visible PM-pillar KPIs for the team |
| `04-automated-pm-report/` | 4 | Automated weekly PM report | Python, pandas, automation | hours saved every week |
| `05-vibration-trend/` | 4 | Vibration trend and P-F evidence | Python, condition monitoring | supports the sensor rollout |
| `06-weibull-pm-study/` | 5 | Weibull PM interval study | statistics, reliability, RCM | evidence-based PM optimisation |
| `07-bearing-anomaly-detector/` | 6 | Bearing anomaly detector | ML, signal processing | ready for real condition-monitoring data |

## Top-level README for the portfolio repo

- Two lines about you: *"Mechatronics apprentice moving into reliability engineering and maintenance analytics."*
- A grid of the 7 projects, each with a screenshot, a one-line result and a link.
- The tools you used.
- Pin the repo on your GitHub profile, and link it from your CV and LinkedIn.

# Practice data: Line D (synthetic)

A fictional cereal line with seven zones, two years of maintenance and production history (**1 Jul 2024 – 30 Jun 2026**), a CMMS migration example, and vibration data. **Nothing here is real company data.** It's generated by [`generate_data.py`](generate_data.py) with a fixed seed, so every run produces identical files and the lesson answers always match.

```powershell
python data\generate_data.py      # rebuilds everything below in ~2 seconds, standard library only
```

## Production tables (in `production/` and `line_d.db`)

### `shifts` (1,460 rows), one row per shift (Days 06:00–18:00, Nights 18:00–06:00)
| Column | Notes |
|---|---|
| shift_id | **PK**, `Snnnnn` |
| line, production_date, shift, crew, sku | production date = the date the shift started; crews A–D; 4 SKUs |
| shift_min | 720 |
| planned_stop_min | breaks (30) plus a weekly deep clean on Sunday days (240) |
| planned_production_min | shift_min − planned_stop_min |
| downtime_min, run_min | run = planned − downtime |
| ideal_rate_ppm | ideal packs per minute for the SKU |
| total_count, good_count, reject_count | packs |

**OEE** = Σ(good_count ÷ ideal_rate_ppm) ÷ Σ planned_production_min. That's 70.3 % over two years and 71.9 % for H1 2026.

### `redzone_downtime` (6,725 rows), one row per stop as an operator logs it
`event_id, line, production_date, shift, crew, sku, machine, start_time, end_time, duration_min, reason_category, reason, comment`. Categories: Mechanical, Electrical, Operational, Changeover, Material, Quality, People and **Unassigned** (no reason entered). Operators use their own words ("Sealing fault", "Noise / bearing"), and some breakdowns are miscoded as jams. Breakdown stops are logged **before** the matching CMMS work order is raised: usually 0–20 minutes before, sometimes up to 2.5 hours.

### `machine_asset_map` (292 rows)
`machine, asset_id, asset_name`. Packing and end-of-line machines map one to one (`Wrapper 3` → `LD-PPK-003`). Process zones and conveyors are grouped (`Cooker` → ~43 assets).

## CMMS migration tables (in `cmms_migration/` and `line_d.db`)

A **made-up** example in the shape of a Mainsaver → Ultimo style migration (the IDs and structure are illustrative, not the real product's):

- `ultimo_equipment`: 291 new equipment records (`EQ-nnnnn`) with a process-function path
- `asset_id_map`: legacy `LD-…` ID → new `EQ-…` ID. It deliberately contains 1 duplicate row, 3 unmapped legacy assets, and 2 legacy assets merged into one new record.
- `failure_code_map`: 28 legacy codes → object part / damage / cause (ISO 14224 style). Only 8 are filled in.

## Monthly export columns (`exports/work_orders/`)

`WO Number, Asset, Asset Description, Zone, Criticality, WO Type, PM Ref, Description, Failure Code, Raised, Due, Completed, Status, Labour Hrs, Downtime Mins, Technician`. These are the same work orders, flattened the way a CMMS export usually is. Dates are **UK format**, which is why Phase 1 teaches locale-aware typing. Files are split by the month the WO was **raised**.

## How the simulation works (so the patterns you find are real)

- Each asset type has **competing failure modes**, each with its own **Weibull** shape β and life η. Examples: flow wrapper jaws β = 3 (wear-out), jams β ≈ 1 (random), sensors β < 1, and new installs get an extra *Installation defect* mode with β = 0.5 (infant mortality).
- **PM effects:** *Replacement* PMs renew their target mode; *Lubrication* takes 40 % off the target mode's age; *Inspections* sometimes catch a wear-out mode near the end of its life, which creates a planned **Corrective** job instead of a breakdown.
- **PM compliance varies by zone:** Primary Packing (~66 %) and End of Line (~75 %) are deliberately weaker than the others (~82–88 %).
- **Deliberate stories to discover:** the flow wrapper jaw replacement interval (182 days) is far longer than the jaws' life (η ≈ 86 days), which is the Phase 6 study. Late PMs *look* linked to breakdowns until you control for asset type (Week 45). And packing minor stops are stable but large (Week 46).
- **Minor stops** are random short stops (2–15 min), concentrated in packing and end of line, with no work order.
- **Vibration data:** degradation starts at a random point late in each bearing's life (the P on the P-F curve), and RMS, kurtosis, crest factor and temperature then rise along a curve. Waveforms are a shaft tone plus noise, plus outer-race impacts at **BPFO = 3.585 × shaft speed (88.2 Hz)**, ringing a ~1.2 kHz resonance.
